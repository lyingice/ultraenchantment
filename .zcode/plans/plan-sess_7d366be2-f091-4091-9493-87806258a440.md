## 目标与默认假设

按你给出的清单，整体实现 18 个 `ue:*` 效果，并把它们接入当前的“原版附魔根源 + 阶段定义 + `AscensionData.tierLevel`”体系。这里把 `ue:` 视为效果 ID 的简称；实际资源命名空间沿用项目规范使用 `ultraenchantment:*`，避免引入一个未注册的 `ue` 命名空间。

## 总体架构

1. **扩展阶段定义**
   - 在 `StageDefinition` 增加可选的 `ue_effects` 字段。
   - 新增一个可 Codec 序列化的 `UEEffect` 联合类型，按 `id` 分派到 18 种效果记录。
   - 所有数值均支持 `base + per_level * (level - 1)`；概率、比例和上限在解析及运行时统一 clamp。
   - 保留现有 `effects: DataComponentMap`，原版数据驱动效果继续走原来的执行器；新字段只承载必须依赖事件生命周期的扩展效果。

2. **统一效果解析与扫描服务**
   - 新增 `UEEffectLookup/UEEffectService`，从装备、主手/副手和 `AscensionData` 解析当前阶段的效果及 `tierLevel`。
   - 提供按触发者、目标、装备槽和攻击来源查询的纯函数辅助，避免每个事件监听器重复解析阶段数据。
   - 增加递归/重入保护、冷却和服务端权威判断，防止真实伤害、反伤、换位等效果互相触发无限循环。
   - 数据包重载时清理效果缓存，与现有 `ReloadEvents`/`EnchantmentFactory.invalidate()` 同步。

3. **全局配置与数据包配置分层**
   - 具体效果数值放在阶段 JSON 的 `ue_effects` 中，支持不同附魔、不同阶段、不同等级曲线。
   - `UEConfig` 只增加全局安全边界/开关，例如最大真实伤害比例、最大双重保护单件比例、最大递归深度、最大多段跳次数和拾取扫描半径；这样既满足“可配置”，又防止数据包写出失控值。
   - 在 `LineageTable` 增加声明式 helper，让默认阶段效果和现有 `UEStageEffects` 一样从 Java 真源生成，而不是手改 `src/generated`。

## 运行时实现分组

### A. 伤害前/后处理

新增统一的 NeoForge 伤害监听器，按事件阶段分工，并在需要时补充最小 Mixin：

- `percent_damage`：按攻击者当前命中来源的效果，在正常伤害结算前修改攻击伤害百分比。
- `scaling_damage`：按周围符合条件的实体数量计算额外倍率，提供基础倍率、每个实体增量和数量上限。
- `self_vulnerability`：按受击者装备效果在最终伤害阶段增加承伤倍率。
- `double_protection`：在原版护甲与保护已经完成、但生命值尚未扣除的位置乘上每件装备的独立减伤系数；单件 clamp 到 50%，多件按乘法叠加，不复用 EPF/保护上限。
- `damage_dodge`：在伤害真正生效前按概率取消本次伤害。
- `damage_reflect`：在受击事件中按概率将本次实际伤害完整返还攻击者，带反伤重入保护。
- `bypass_iframes`：命中前按概率清理目标的受击无敌帧/伤害间隔；优先使用公开事件状态，必要时对 `LivingEntity` 的受击方法做 Mixin。
- `real_damage`：将命中伤害拆成普通伤害与 `setHealth` 级真实伤害；`ratio + bonus` 形成转换比例并受 `cap <= 100%` 限制，真实伤害部分无视护甲、保护、无敌帧和普通限伤，使用递归保护。
- `hemophagia`：根据目标实际损失的生命值计算吸血，命中后再恢复攻击者，按等级曲线和目标当前缺血量截断。
- `strip_buffs`：命中后移除目标的正面状态效果，按等级决定移除数量，保留负面效果和不可移除效果。

伤害监听器会统一保存“事件前生命值/事件后生命值/原始来源/最终来源”，保证吸血、真实伤害、反伤不会使用错误的预减伤数字。

### B. 死亡保护与实体触发

- `skip_death`：接入死亡事件；成功触发时取消本次死亡、将血量设为 1、清除状态效果，并按配置施加自定义 MobEffect/实体效果。增加每次伤害链只触发一次的标记。
- `be_attacked`：受击成功后根据配置对装备者或攻击者施加指定实体效果，支持目标枚举、自身/攻击者方向、效果时长和等级随阶段等级变化。
- `swap_position`：在命中或受击触发时做安全换位，检查双方维度、碰撞箱、骑乘状态、死亡状态和冷却，失败时不消耗效果。

### C. 盾牌与格挡

- `on_block`：使用 NeoForge 盾牌格挡事件，在成功格挡后触发反击、反弹或实体效果。
- `on_shield_disabled`：接入盾牌被斧类攻击进入冷却的节点；若公开事件无法覆盖进入冷却的瞬间，增加针对盾牌禁用方法的最小 Mixin。
- 两类效果共用触发上下文，避免“格挡”和“盾牌被禁用”同时重复结算；反击伤害带来源标记，防止反复触发。

### D. 移动、投射物和拾取

- `multi_jump`：增加玩家附件中的剩余空中跳跃计数，落地重置；客户端捕捉跳跃输入，服务端验证并执行额外跳跃，数量按等级增加。
- `projectile_speed`：在投射物生成/首次 tick 时按持有者效果修改初速度；只处理效果允许的箭矢和投掷物，避免重复乘速。
- `auto_pickup`：在掉落生成时记录原主人 UUID，在 `ItemEntity.playerTouch`/拾取事件前拦截；仅在线、主人匹配且背包有空间时直接回收，否则保持原版掉落。

## 阶段数据接入

1. 在 `LineageTable` 增加 18 个 helper 和默认参数模板，按现有阶段的绝对数值语义填写高阶/超级/究极配置。
2. `UEStages` 生成 JSON 时同时写入原版 `effects` 和 `ue_effects`。
3. 将 `ue_effects` 纳入阶段 Codec、网络同步、重载缓存和客户端 tooltip/效果总表展示。
4. 对每个效果增加 schema 校验：比例范围、chance 范围、cap 不超过 1、`double_protection` 单件不超过 0.5、等级上限、空目标效果和互斥参数均在 datagen 阶段报错。
5. 生成对应中英文本地化键；不改变已有阶段 ID 和原版附魔显示兼容行为。

## 文件层面的主要改动

- `content/StageDefinition.java`：增加 `ue_effects` 及 Codec。
- `content/UEEffect.java`、`content/UEEffectTypes.java`：效果记录、联合 Codec、等级曲线。
- `logic/UEEffectLookup.java`、`logic/UECombatContext.java`：阶段效果解析与触发上下文。
- `event/UECombatEvents.java`、`event/UEShieldEvents.java`、`event/UEPickupEvents.java`、`event/UEMovementEvents.java`：运行时监听器。
- `mixin/`：仅补充公开事件覆盖不到的无敌帧、盾牌禁用、跳跃输入、物品实体拾取节点。
- `datagen/UEStageEffects.java`、`datagen/UEStages.java`、`datagen/LineageTable.java`：默认效果声明和生成。
- `UEConfig.java`：全局安全边界。
- `Ultraenchantment.java`：注册新增 game-bus 监听器及必要的 Mixin 入口。
- `src/main/resources` 与生成资源：Mixin 配置、阶段 JSON、语言文本。

## 验证方案

1. 先增加纯逻辑测试/运行时探针，覆盖等级曲线、概率 clamp、真实伤害拆分、独立减伤乘区、反伤重入和死亡保护单次触发。
2. 执行 `gradlew runData`，确认所有阶段 JSON、Codec 和语言键生成成功，且没有重复属性/断链。
3. 执行 `gradlew build`，检查 NeoForge 1.21.1 API、Mixin 注入点和客户端/服务端类加载隔离。
4. 执行 `gradlew runServer` 做伤害、死亡、盾牌、换位、拾取和数据包重载探针。
5. 对多段跳、投射物速度、tooltip 和客户端输入执行 `gradlew runClient` 验证。
6. 保留并汇报现有工作区修改，不覆盖 `.idea/workspace.xml`、`AGENT.md`、`build.gradle`、`gradle.properties` 中用户已有改动。

实现顺序会先落地 Codec/解析层和纯数值伤害管线，再接入死亡/盾牌/移动/拾取 Mixin，最后生成全部阶段数据并做完整构建验证。
