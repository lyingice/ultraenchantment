## 3. 载荷 schema

### 3.1 载体书（铭刻型）

组件 id：ultraenchantment:inscription_spec

    {
      "tier": "advanced",
      "entries": [
        { "enchantment": "minecraft:sharpness", "level": 3 },
        { "enchantment": "minecraft:looting",   "level": 2 }
      ]
    }

| 字段 | 类型 | 约束 |
|---|---|---|
| tier | AscensionTier | **书级单值**：本书所有条目同阶级。必非原生阶 |
| entries | list | **至少 1 条**；建议上限 8（仅 tooltip 折叠用，不强制） |
| entries[].enchantment | ResourceLocation | 原版附魔 id |
| entries[].level | int 1..255 | **语义 = tierLevel（曲线等级）**，不是存储等级 |

> **为什么 level 必须是 tierLevel**：存储等级升阶后永远是上限，把它 +1 得到的数字对强度毫无作用，
> 合并就变成空转。选 tierLevel，「两本同级书 → 升 1 级」才真的变强。

**实际生效值一律夹在该谱系该阶的 max_level 内**（逐谱系查，见 P1-28 的 StageLookup.maxLevelOf）：
耐久 3、保护 4、锋利 5。书里写 5、该阶上限 3 → 生效 3。

### 3.2 其余两类书（不变）

| 组件 | 科目 | 载荷 |
|---|---|---|
| ultraenchantment:ascension_spec | 进化型 | from_tier / to_tier / applicable |
| ultraenchantment:upgrade_spec | 升级型 | tier / target_level |

## 5. 铭刻书（载体书）逐条规则

### 5.1 贴到装备 · 生存模式（= 铭刻型升级书）

对每个条目独立判定：

| 条件 | 结果 |
|---|---|
| 装备上该谱系**无记录（原生阶）** | **拒绝** → 进剩菜 |
| 装备上该谱系阶级 == 书的 tier，且 entry.level > 当前 tierLevel | **生效**：tierLevel = min(entry.level, 该阶 max_level)；存储等级不动 |
| 装备上该谱系阶级 == 书的 tier，但 entry.level <= 当前 tierLevel | **拒绝** → 进剩菜（无变化） |
| 装备上该谱系阶级 != 书的 tier | **拒绝** → 进剩菜 |

> 等价说法：生存模式下它就是「升级书的附魔限定 + 多条目版」——不能凭空给装备上一个阶级。
> 想给白装备上高阶，必须走进阶书（原生→高阶）。

**一条都没生效 → 不产出**（输出槽为空，书不消耗，等于原版"无效操作"）。

### 5.2 贴到装备 · 创造模式（旁路）

| 差异 | 说明 |
|---|---|
| 放开「必须已有记录」 | 原生阶装备也接受：写入该谱系该 tier 的阶段条目，tierLevel = min(entry.level, 该阶 max_level)，**存储等级设为该阶 max_level** |
| 允许直接上究极 | ULTRA 载体书贴白装备 → 该谱系直接进究极阶（**跳过中间阶级**，这是刻意允许的调试能力） |
| 已有记录但阶级不同 | **仍拒绝**（防降级）【待确认 §9-6】 |
| 物品是否支持该附魔 | **不放开**：仍要求该物品 supportsEnchantment（照原版），否则锋利能刻到镐子上 |

> 旁路判据与现有实现一致：玩家 isCreative()，与进阶书的创造旁路同源。

### 5.3 剩菜（部分生效时的第二输出）

**定义**：本次**没有改变装备**的条目（被拒绝的 + 无变化的）。

**交付方式**：铁砧只有一个输出槽，无法原地留下第二件物品。因此：

1. AnvilUpdateEvent 阶段只设输出 = 装备（纯函数，两侧一致）；
2. AnvilRepairEvent（**服务端**，在槽位被清空前触发）用同样的输入重新解析一次，得到剩菜条目 → 重建一本载体书 → 进玩家背包；背包满则掉落。

| 剩菜书属性 | 值 |
|---|---|
| 阶级 | 与原书相同（转手不会改阶级） |
| 条目 | 只剩没吃下去的，level 原样 |
| 条目为 0 | 不交付（整本都被吃掉了） |

> 这是全模组**唯一**需要「第二输出」的操作。备选交付方式（把剩菜写回右槽）依赖菜单内部状态、且与清空槽位的顺序竞态，已否决。

### 5.4 书 + 书（铁砧合并）

| 情形 | 结果 |
|---|---|
| 同 tier | 条目**并集**；同一附魔：level 相等 → **+1**（夹该谱系该阶 max_level）；不相等 → **取 max** |
| 不同 tier | **拒绝**【待确认 §9-2：可选"低品质向高品质合并"】 |
| 互斥附魔（锋利 / 亡灵杀手） | 允许共存于书（与原版一致），贴到装备时才判 areCompatible |
| 结果为空 | 不产出 |

**这一条就是"同名合并升 1 级"在书层面的落地**（README §2 早就写了，一直没实现）。

### 5.5 转印（原版附魔书 → 载体书）—— 回答问题一

    原版附魔书 + 「基础→高阶」进阶书
      → 输出 ultraenchantment:advanced_enchanted_book
      → 载荷 { tier: ADVANCED, entries: [书上每条附魔 → level 1] }

| 规则 | 说明 |
|---|---|
| 门槛 | 每条附魔：原版书上的存储等级 ≥ min(目标阶 required_level, 原版 max_level)。锋利 → 必须有一本**锋利 V** 的原版书。**复用现成代码**（LineageTier.NATIVE 分支就是这么算的） |
| 条目 level | 一律 = **1**（曲线起点）。原版书上的 V 的价值体现在"够得上门槛"，与 v1 的「升阶后曲线归 1」同构 |
| 部分通过 | 默认【整本必须全部过门槛，否则不转】【待确认 §9-1】 |
| 产物 | 物品 id 变成我们的书（"是物品转变为进阶附魔书吗" → **是**） |
| 为什么必须有 | 生存模式下载体书不能贴白装备（§5.1），转印是**生存唯一获得载体书的渠道** |

## 6. 装备层同名合并（决定 4）

| 项 | 规则 |
|---|---|
| 触发 | 左槽与右槽是**同一物品**，且**两侧都有阶段记录** |
| 参与合并的谱系 | 两侧都存在、且**阶级相同**的谱系 |
| 同级（tierLevel 相等） | **+1**（夹该谱系该阶 max_level） |
| 不同级 | **取 max**（照原版）【待确认 §9-5：可选"只做同级 +1"】 |
| 阶级不同的谱系 | 不参与（不搬运、不取 max：避免靠吃掉一件高阶装备跳阶） |
| 其余一切 | **照原版**：耐久合并（含 12% 加成）、其他原版附魔合并、兼容性判定、先修惩罚 ×2+1、成本 |
| 其余情况 | 交回原版（非同名 / 任一侧无记录 → 行为完全不变） |

**代价（必须知情）**：这一条要求我们接管原版的合并数学——
即主动放开 AGENT.md **P1-13**「不在此重写原版的合并数学」的约定。
需要忠实搬进来：耐久合并公式、附魔合并循环（同级 +1 / 取 max / 夹 max_level）、
REPAIR_COST 的 calculateIncreasedRepairCost、成本累加。约 60~80 行 + 一个逐项对照原版的测试矩阵。

## 7. 成本表（v2）

| 操作 | 公式 | 例（锋利） |
|---|---|---|
| 进阶书（升阶） | 目标阶 anvil_cost | 3 / 5 / 7 |
| 升级书 | 固定 3 | 3 |
| 载体书 → 装备 | Σ max(1, anvil_cost/2) × 生效 tierLevel，最小 1【待确认 §9-7】 | 1 条 tierLevel 3 → 3 |
| 书 + 书 | Σ max(1, anvil_cost/2) × 结果 level + 先修惩罚 | 锋利 3+4 → 4 |
| 转印 | 进阶书的 anvil_cost | 3（基础→高阶） |
| 装备同名合并 | Σ 阶段 anvil_cost × 结果 tierLevel + 先修惩罚 ×2+1 | 高阶锋利 2+1 → 3×3=9 + 先修 |

> 一律**不低于 1**（cost == 0 → mayPickup 恒 false，输出拿不走，P0-5）。
> 被我们接管的操作**不会触发 40 级「过于昂贵」上限**（该分支在 setOutput 后被跳过）——这是既有行为，v2 不变。

## 8. 与原版铁砧的差异（v2 更新）

| 机制 | 原版 | 我们（接管时） |
|---|---|---|
| 等级上限 | 夹到 enchantment.getMaxLevel() | 不夹（写进去的本来就 ≤ 该阶 max_level） |
| 同名合并升 1 级 | 对**存储等级**生效 | 对 **tierLevel** 生效（§6） |
| 先修惩罚 | 每次合并 ×2+1 | 装备合并照原版；纯升阶 / 升级 / 载体书操作**不写**（永不涨价） |
| 40 级上限 | cost ≥ 40 → 输出清空 | 绕过，**永不触发** |
| 重命名 | +1 级，与操作同时生效 | 我们的分支**不读名称框 → 重命名被丢弃**（v2 未修，已知缺口） |
| 书 + 书 | 原版附魔书合并 | 我方书合并（§5.4）+ 原版书仍走原版 |
| 第二输出 | 无 | 剩菜书通过 AnvilRepairEvent 交付（§5.3） |
| 原版附魔书贴装备 | 正常 | **不变**（我们不接管，进阶状态不会跟着书走） |

## 14. v2.1 修正：创造栏铭刻书的排布

两个「看起来像数据坏了、其实只是排布错了」的问题，都已修：

| 症状 | 真因 | 修法 |
|---|---|---|
| 主标签读到「高阶X / 超级Y / 究极Z」，像阶级串了行 | v1.3 起的**阶级轮转取样**（每条谱系只露面一次，阶级按谱系序号轮转） | 改为**谱系外层 × 阶级内层**：每条谱系 × 每个阶级各一本满级书，同一附魔的三个阶级相邻且递增（30 → **90** 条） |
| 某条谱系的书「多了一条别的附魔」（实测：引雷的书里出现爆炸保护） | v2.0 新增的**多条目「已合并」样本**摆在主标签；它与单条书**共用同一材质**（区分只有「科目 × 阶级」），于是看起来像串数据。排序后前两条谱系恰好是爆炸保护与引雷，三条样本内容全同 | 多条目样本**移到搜索标签**（全规格区）；主标签只放单条目书 |

顺序契约由 `CreativeTabEvents.mainTabInscriptions()`（纯函数）承载，并被自检直接断言
（8 项：计划条数、谱系外层、阶级内层严格递增、逐谱系逐阶级满级、主标签只含单条目）。
之所以抽出来，是因为**这种顺序没有任何界面能自动断言**。

## 15. 提示框规格（从 README 移交，实现契约）

全部走翻译键 + 占位符，不用字面量拼接（专用服务器没有语言数据，P1-17）。

**通用约定**：标题行金色 · 标签行暗灰 · 附魔行与阶级名行用普通附魔同色（GRAY）·
阶级配色 高阶 = 蓝 / 超级 = 淡紫 / 究极 = 金，与附魔行上的阶级色一致。

### 15.1 进化型 · 通用进阶

    h1  附魔进阶
    h2  可应用于附魔：
    h3  普通附魔 / 高阶附魔 / 超级附魔
    h4  进阶为：
    h5  高阶附魔 / 超级附魔 / 究极附魔

| 品质 | h3 | h5 |
|---|---|---|
| 基础→高阶 | 普通附魔 | 高阶附魔 |
| 高阶→超级 | 高阶附魔 | 超级附魔 |
| 超级→究极 | 超级附魔 | 究极附魔 |

通用进阶不写具体附魔名，只写阶级范围。

### 15.2 进化型 · 定向进阶

**h3 写「上一阶」，不是原版附魔名。** 定向书是「限定谱系的通用进阶书」，
描述的同样是链上的一条边：

- `h3`（可应用于附魔）= `from_tier` 那一阶的名称；只有 `from_tier` 是原生阶时，
  「上一阶」才恰好就是原版附魔本身。
- `h5`（进阶为）= `to_tier` 那一阶的名称。

| 品质 | h3 | h5 |
|---|---|---|
| 基础→高阶 | 锋利（原生阶退原版附魔名） | 高阶锋利 |
| 高阶→超级 | 高阶锋利 | 超级锋利 |
| 超级→究极 | 超级锋利 | 究极锋利 |

（早期实现把 h3 一律写成原版附魔名，读起来像「原生锋利直接推到超级」，规格与实现均已更正——见 AGENT.md P1-30。）

### 15.3 铭刻型 = 载体书

    h1     高阶附魔
    h2..hN 高阶锋利 IV
           高阶抢夺 III        ← 每条目一行，多条目书就是多行

- `h1` = 阶级名 + 「附魔」；
- `h2..hN` = 该阶级附魔的**独立本地化名**（`高阶锋利`，不是「阶级词缀 + 原版名」拼的）+ 曲线等级；
- 等级省略规则照原版：**1 级且该阶级上限为 1** 才省略数字（见 P1-32）。

### 15.4 升级型

    h1  高阶升级 III
    h2  可应用于附魔：
    h3  高阶附魔

`h1` 中的罗马数字 = 本书可把附魔提升到该等级。

### 15.5 祛咒石

    h1  可应用于：
    h2  高阶附魔 / 超级附魔 / 究极附魔

结构与升级书的前两行同源（同一套 `applies_to` / `tier_scope` 键）。
