# 附魔图书馆 · 能量模型 v5：阶级书库存化

> **状态**：**已实现**（v5）。取代 v4 的「阶级单位点数池」。
> **来源**：2026-10 与作者的一轮架构审查（对照神化源码 + 灌注台源码取证），结论见 §1.3。
> **目标读者**：实现者。改完必须同步本文与 `AGENT.md`。

---

## 0. 一句话

> **图书馆是电池（等级单位），进阶书是钥匙。**
>
> 图鉴管「你能取什么」，**书**管「你能不能跨过去」，**等级单位**管「你能提多高」。

---

## 1. 为什么从 v4 改到 v5

### 1.1 v4 是什么

v4 存 **8 类抽象能量**（2 家族 × 4 阶级，不分谱系）：

```
                基础    高阶    超级    究极
阶级单位(进阶)   ——      5      10      20     ← 点数，升阶花它
等级单位(提级)   ?       ?       ?       ?     ← 点数，提级花它
```

升阶价 = `required_level × 阶级系数`，同类内 4:1 向上兑换。

### 1.2 三个问题

1. **它把「钥匙」变成了「燃料」。** 一本进阶书是**离散**的；折成点数之后，玩家会算
   「我还差 3 点」，而不是「我还差一本超级书」。这与本模组「进阶书 = 钥匙」的
   核心直觉正面冲突。
2. **4:1 向上兑换把稀缺性抹平了。** 低阶书好拿（学徒级村民、普通战利品），
   高阶书稀缺（大师级村民、BOSS）。兑换把这条曲线压平 —— 稀缺资源变成可刷。
3. **它需要一条手写的守恒律。** v4 后期为了让「一步到位不比一步步走便宜」，
   加了一条公式：`Σ 跳过每一档的价 + Σ 中间阶级满级价 + 目标价`。
   **一条需要手写出来才能维持的守恒律，通常说明模型选错了** —— 钥匙天然守恒；
   被拆成硬币的东西才需要定价规则去缝。

### 1.3 一条硬证据（v5 的触发点）

同一件事，模组里当时有**两套互相矛盾的经济**：

| 路径 | 代价 | 代码 |
|---|---|---|
| 铁砧 | **用掉那本进阶书** + 经验 | `AscensionLogic.resolveAscension` |
| 进阶台 | **花阶级单位点数**，不需要书 | `AscensionTableMenu.tierCostOf` |

⇒ 只要存在一条「不用书也能升阶」的路，**书就不再是钥匙，而是一张打折券**。
v5 把两条路统一到「书」上：**怎么升阶，只有一个答案 —— 拿对应的书。**

## 2. 数据结构

`EnchantmentLibraryBlockEntity` 三块存储（**8 个桶 → 4 + 2 张表**）：

| 块 | 类型 | 维度 | 说明 |
|---|---|---|---|
| 等级单位 | `int[4]` | `LineageTier.ordinal()` | 提级燃料；**基础阶也有效**（原版附魔书产出它） |
| 通用进阶书 | `int[4]` | `LineageTier.ordinal()` | 只有 3 档有效（基础阶没有进阶书） |
| 定向进阶书 | `Map<LineageTier, Map<ResourceLocation, int>>` | 阶级 → 谱系 | 只对钉住的那条谱系有效 |

**NBT 键**：

| 键 | 形态 |
|---|---|
| `level_energy` | `{native: 4, advanced: 12, ...}` |
| `generic_books` | `{advanced: 2, super: 1}` |
| `targeted_books` | `{advanced: {"minecraft:sharpness": 2}}` |
| `energy`（v4 遗留） | **只读**。取其中的 `level|<tier>`；`ascension|<tier>` **丢弃** |

**单条书库存上限** `MAX_BOOKS = 999`：给 GUI 一个确定的天花板，也让「整本吸收」的原子性有明确判据。

## 3. 存入

| 书 | 产出 |
|---|---|
| 原版附魔书（基础阶） | 等级单位·**基础** += `Σ f(level)`；并把谱系记为「见过」 |
| 铭刻书 | 等级单位·该阶级 += `Σ f(entry.level)` |
| 升级书 | 等级单位·该阶级 += `f(targetLevel) × 4`（通用加成） |
| **进阶书 · 通用** | **通用进阶书·目标阶级 ×1** |
| **进阶书 · 定向** | **定向进阶书·目标阶级·该谱系 ×1** |

- `f(L) = 2^(L-1)`，与 v4 完全一致。
- **`toTier == NATIVE` 的进阶书拒绝存入**（基础阶不是可推进到的目标，那是原版附魔书的领域）：
  记 WARN，**整本留在输入槽**。
- **整本吸收的原子性不变**：任一桶装不下就整本留下 —— 部分吸收会静默吞掉玩家的书。

## 4. 取出

图书馆**只剩下一种取出**：用等级单位换铭刻书，仍然是「一级一级加」
（左键 = 输出槽那本书 +1 级、只付边际差；Shift+左键 = 1 级）。

**阶级书库存不能取出**。它只能被进阶台消耗 —— 图书馆不再是兑换所。

### 4.1 一行一条谱系（v6）

列表**按谱系去重**：一条附魔一行，行内用「阶级 −/+」挑档次、「等级 −/+」挑等级，
再按行尾的**取出**小按钮。这样一条附魔解锁四档也只占一行（此前是四行）。

**取出的定价**：`花费 = f(等级)`，一次付清。
它与旧版「一级一级点、只付边际差」的**总价完全相同**
（`f(1) + (f(2)−f(1)) + … = f(n)`），区别只在于**不再有一个藏在输出槽里的隐藏状态**。

> ⚠️ **别再引入「输出槽里那本书的等级」这种状态。** v6 之前正是它导致
> 「点一下别的条目，没拿走的书连同已花的等级单位一起消失」——
> 状态藏在一个玩家看得见的物品里，而覆盖它的时候没有任何提示。

**三道保险**（缺一不可）：
1. 输出槽非空 ⇒ **拒绝**新的取出，并明说「先把书拿走」；
2. 行内 / 按钮 / 服务端三处用**同一个判据**检查余量；
3. 关界面时把输出槽**还给玩家**（`clearContainer`，不会蒸发）。

## 5. 库存模型：不再有「折算」

v4 的整节「折算公式」（升阶价、阶级系数、兑换率）**全部删除**。理由：

> **进阶书本身就是离散的，折成点数是多余的中间层。**

点数只在这三种情况下才划算：① 单位与单位之间需要连续换算（等级 2↔3 是同一维度的伸缩）；
② 需要「零钱凑整」；③ 需要跨种类转换。**进阶书的场景一条都不占** ——
它已经是「一本一个」的东西，玩家也从来不需要半本书。

### 5.1 删掉的符号（不要再加回来）

`EnergyFamily.ASCENSION`、`EnergyMath.ascensionPrice`、`EnergyMath.tierCoefficient`、
`EnergyMath.GENERIC_ASCENSION_BASE`、`EnergyMath.EXCHANGE_RATE`、`EnergyMath.exchangeYield`、
以及「4:1 向上兑换」的全部实现。

**`EnergyFamily` / `EnergyKey` 两个类整个删除**：只剩一个「家族」时，
键退化成阶级本身，保留它只会让人以为还有第二个家族。

## 6. 升阶：进阶书的消耗

> **用词**：本文下称「钥匙」是设计时的比方，**界面上这一列叫「书耗」** ——
> 玩家要的就是「进阶书」这个实物，不必先理解比方。代码标识符仍用 `keyBook`。

进阶台的一行选中目标阶级后：

1. 目标阶级 `toTier`（高阶 / 超级 / 究极）与谱系 `rootId` 已定；
2. 按顺序找一本可用的书（见 §6.1）；
3. 找到 → 消耗一本，写 `ascension` 组件；找不到 → 状态码 `STATUS_NO_KEY_BOOK`；
4. **不再校验任何点数** —— 书本身就是唯一代价。

### 6.1 消耗优先级：先定向、后通用

```
targetedBooks[toTier][rootId] > 0  →  消耗一本定向书
否则 genericBooks[toTier]      > 0  →  消耗一本通用书
否则                                  →  缺书，升不了
```

**为什么是这个顺序**：定向书只能用于它钉住的那条谱系，通用书能用于任意谱系。
所以玩家留通用书去应付别的谱系**永远更划算** —— 这是玩家的最优策略，
直接做成默认行为，不需要玩家手动选。

**跨多座图书馆时**：先把环内所有图书馆的定向书扫一遍，再扫通用书。
**不是**「按图书馆逐座用完」—— 那样先遇到的那座图书馆会用通用书顶掉后面的定向书。

### 6.2 通用 vs 定向

| 维度 | 通用进阶书 | 定向进阶书 |
|---|---|---|
| 存储 | `genericBooks[tier]` | `targetedBooks[tier][root]` |
| 可用范围 | **任意**谱系 | **仅** `root` 这条 |
| 消耗优先级 | 次选 | **首选** |
| 获取难度 | 高（大师级村民 / BOSS 掉落） | 低（学徒级村民 / 随机掉落） |
| 图书馆 GUI | 「×N」里的通用计数 | 同格总数里；悬停看「锋利 ×2 / 保护 ×1」 |

### 6.3 跨阶跳跃：跨几档收几本（**方案 B，作者 2026-10 拍板，已实现**）

```
消耗本数 = max(0, toTier.ordinal() - fromTier.ordinal())

  基础 → 高阶 = 1 本
  高阶 → 超级 = 1 本
  基础 → 究极 = 3 本      ← 与「一步步走」总消耗相同
  究极 → 高阶 = 0 本（往低阶不收费）
  同阶级提级  = 0 本（那不是升阶）
```

**为什么不是「一次只收一本」（方案 A）**：那样 `基础 → 究极` 只花 1 本究极书，
而逐级走要 3 本 —— 这不是「便宜一点」，是**结构性的定价倒挂**。
v4 靠一条手写的「完整路径定价」公式堵这个洞；v5 删掉那套公式之后，
唯一还能正确表达同一件事的东西就是**数量**：
> **「完整路径」＝「把那几档的书都付了」。**

**为什么不是「禁止跳阶」（方案 C）**：那会把 `基础 → 究极` 这条合法路径整个砍掉，
是**改玩法而不是修定价**；而且与 `next` 链允许跳过的语义冲突 ——
既然链上允许跳过，书就不该不允许。

**边界（作者确认）**：只有 1 本究极书时从基础跳究极会**失败**（需要 3 本）。
这是对的：玩家要么攒够 3 本一次跳，要么逐级走（各 1 本，也是 3 本）。
**两条路代价相同，玩家自己选。**

**实现**：`KeyBooks.required` 一行。GUI 的「N 本 / 缺 N 本」与实际扣减本来就按**数量**处理
（`hasEnough` + `AscensionTableMenu.consumeKeyBooks`），所以策略换了它们一行都不用动 ——
这正是「把判定集中在纯函数里」的回报。

## 7. 提级：等级单位

```
花费 = f(目标等级) - f(同阶级已有等级)      f(L) = 2^(L-1)
```

**带符号**：正 = 扣，负 = 退还。降级会把差额退回环内图书馆（v4 已实现，v5 不变）。

⚠️ v4 附加的「中间阶级满级价」那一项**已删除** —— 它只服务于「完整路径定价」，
而升阶的代价现在是书。

## 8. 图鉴的职责（未变）

图鉴仍然决定「这条谱系的这一档你能不能**选**」。与钥匙不重叠：

| | 回答的问题 | 载体 |
|---|---|---|
| 图鉴 | 你**知不知道**这一档存在 | 玩家附件 `CodexData` |
| 进阶书 | 你**能不能**跨过去 | 方块库存 |
| 等级单位 | 你能**提多高** | 方块库存 |

### 8.1 图鉴是「向下闭包」的

解锁某一档 ⇒ **自动解锁它的全部下级阶级**（含基础阶）。
拿到一本「究极锋利」当然意味着你知道「高阶锋利」是什么 ——
它们是同一条谱系的前几段。只点亮一格会造成荒谬情形：
**物品带着究极锋利，却选不了它的高阶档。**

### 8.2 物品缓存：让玩家能编辑自己已有的东西

放进进阶台的物品，**它自己带着的每条谱系**，其所在阶级**及所有下级阶级**一律可选 ——
与图鉴**取并集**，但**不写回图鉴**。

理由：物品可能是捡的、别人给的、创造栏拿的，玩家从没「见过」它的书。
若只看图鉴，就会出现「我手里这把剑带着高阶锋利，可我就是改不了它」。
**物品缓存只对这件物品上真有的谱系生效**（不会凭空解锁别的附魔），换一件物品即重算。

一句话区分：**图鉴记「你见过什么」，物品缓存只管「你能不能编辑自己手里的东西」。**

## 9. 走一遍玩家的实际流程

| 步骤 | 结果 |
|---|---|
| 捡到「锋利 III」铭刻书（高阶）→ 存进图书馆 | 等级单位·高阶 += 4 |
| 又存一本「耐久 II」铭刻书（高阶） | 等级单位·高阶 += 2（**同桶**） |
| 存一本「基础→高阶」定向锋利进阶书 | **定向进阶书·高阶·锋利 ×1** |
| 进阶台上给剑升到高阶 | **消耗那本定向书**（不是通用书），物品拿到 `advanced/sharpness` |
| 在高阶内把 1 级提到 3 级 | 等级单位·高阶 -= `f(3) - f(1)` = 3 |
| 想再上超级 | 需要一本**超级**进阶书 —— 攒不到就上不去 |

## 11. 决策记录（含被否选项）

| # | 决策 | 被否掉的 | 理由 |
|---|---|---|---|
| 1 | 阶位 = **离散书库存** | 阶级单位点数池（v4） | 点数把钥匙拆成硬币；玩家会算「还差 3 点」 |
| 2 | 关闭跨阶级兑换 | 4:1 向上兑换（v4） | 兑换把低阶书的充裕直接变成高阶书的供给，稀缺性被抹平 |
| 3 | 图书馆**不参与**阶位判定之外的任何事 | 图书馆也管阶位（v4） | 一个方块一个身份；玩家不用猜「这本书该存还是该留」 |
| 4 | 优先消耗**定向**书 | 让玩家手选 / 优先通用 | 留通用书应付别的谱系是玩家的最优策略，做成默认即可 |
| 5 | 进阶书在**进阶台**消耗，铁砧保持原样 | 两条路都用点数 | 铁砧那条一直是「用书」，台子那条是异类 |
| 6 | 旧存档阶级单位**直接丢弃**，不做换算 | 自动换算成书 | 点数是「元」、书是「本」，无损换算不存在；开发期无真实存档 |
| 7 | `toTier == NATIVE` 的进阶书**拒绝**存入 | 静默忽略 | 那是个无意义的载荷；WARN + 留在槽里，作者能立刻看见 |
| 8 | 单条书库存上限 999 | 无上限 | 防溢出，并给「整本吸收」一个明确判据 |
